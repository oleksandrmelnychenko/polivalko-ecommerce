# Товарний фід для Google Merchant Center

Погоджено з власником 2026-11-26 («Так, роби»).

## Навіщо

Сайт новий, і в звичайному пошуку Google його товарів майже не видно. Безкоштовні товарні оголошення
Merchant Center показують товар із фото й ціною, не чекаючи, поки сайт набере вагу. Для цього Google потрібен
файл із товарами, який він сам забирає раз на добу.

## Що було

- Сторінка товару віддає розмітку `Product` з `Offer`, але фіда немає.
- У sitemap і в пошук ідуть товари з фото (`GetSitemap.cs`, `isIndexableProduct`); правило про ціну там не діє.
- Каталог станом на 26.11.2026: 4 935 товарів, з них 2 435 мають і ціну, і фото. Артикули серед них не
  повторюються, назв довших за 150 символів немає.

## Підходи

1. **Файл фіда на вітрині, який Google забирає сам.** Обрано: дає контроль над полями й одразу віддає всі товари.
2. **Автоматичне зчитування сайту самим Merchant Center** за розміткою сторінок. Коду не потребує, але для нового
   сайту повільне й без контролю над полями (GTIN, шлях розділів, додаткові фото).
3. **Надсилання товарів через Content API.** Оновлення майже миттєві, але потрібні ключі Google і фонова
   задача; для каталогу, де ціни й залишки міняються рідко, це зайве.

## Як працює

**Адреса:** `/feeds/google-merchant.xml` на домені магазину. XML у форматі RSS 2.0 з простором імен
`http://base.google.com/ns/1.0`.

**Які товари:** видимі товари, що мають ціну понад нуль і хоча б одне фото. Розпродані лишаються у фіді з
`out_of_stock`. Товар без ціни чи без фото Google не приймає.

**Поля:**

| Поле фіда | Звідки |
|---|---|
| `g:id` | артикул; якщо артикул повториться у фіді, його лишає за собою товар зі старшим ідентифікатором, решта отримують власний ідентифікатор товару |
| `title` | назва товару, до 150 символів |
| `description` | текст опису без розмітки, до 5 000 символів; якщо опису немає — назва |
| `link` | адреса сторінки товару на основному домені |
| `g:image_link`, `g:additional_image_link` | перше фото й до десяти наступних (оригінали, не зменшені копії) |
| `g:availability` | `in_stock`, якщо товар можна купити, інакше `out_of_stock` |
| `g:price`, `g:sale_price` | ціна в `UAH`; якщо є стара ціна, вона йде в `g:price`, а поточна — в `g:sale_price` |
| `g:brand` | бренд, якщо заданий |
| `g:gtin` | штрихкод, якщо це справжній GTIN (та сама перевірка, що в розмітці товару) |
| `g:mpn` | характеристика «Модель виробника», якщо є |
| `g:identifier_exists` | `no`, лише коли немає ні бренду, ні GTIN, ні моделі. Google дозволяє `no` тільки тоді, коли виробник точно не присвоїв товару ідентифікаторів; для товару з брендом цього напевно не знаємо, тому поле не подаємо |
| `g:product_type` | шлях розділів: «Все для поливу > Шланги» |
| `g:condition` | `new` |

**Дані:** новий запит `GET /api/v1/catalog/merchant-feed` віддає товари для фіда одним списком, за тим самим
зразком, що `GET /api/v1/catalog/sitemap`. Вітрина складає з нього XML у маршруті
`app/feeds/google-merchant.xml/route.ts`; дані кешуються на години й скидаються разом із каталогом. Якщо API не відповів або повернув порожній список,
маршрут відповідає помилкою 500: порожній файл з кодом 200 змусив би Merchant Center прибрати всі товари.

**Повернення в розмітці:** `Organization` на сайті отримує `hasMerchantReturnPolicy`: Україна, обмежений строк,
14 днів (зі сторінки «Повернення й обмін»). Хто платить за зворотну доставку, сторінка не каже, тому це поле не
заповнюється.

## Не робимо

- Доставку у фіді: тариф перевізника не фіксований, вона налаштовується в самому Merchant Center.
- `google_product_category`: Google призначає категорію сам; шлях розділів іде в `product_type`.
- Товари без ціни чи без фото, варіанти товарів (`item_group_id`): груп варіантів у даних поки немає.
- Надсилання через Content API й окремі фіди для реклами.

## Перевірка

- Тест API: у фід потрапляє товар із ціною і фото (також розпроданий), а товар без ціни чи без фото — ні.
- Тести вітрини: XML для товару з усіма полями, товару без бренду й штрихкоду, товару зі старою ціною;
  екранування спецсимволів; запасний ідентифікатор при повторі артикула.
- Локальна збірка: файл розбирається як XML, кількість товарів збігається з відповіддю API.
- Після розгортання: `curl` адреси фіда, кількість товарів близько 2 435; далі власник додає адресу в Merchant
  Center і дивиться діагностику там.
